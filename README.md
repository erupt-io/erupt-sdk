# erupt-sdk

Serve models from any language as erupt admin pages. A node owns models and data; the erupt server
renders the admin UI, logs users in and checks menus. Wire contract: `erupt-cloud/PROTOCOL.md` in the
erupt repository.

| Dir | Language | Package |
|-----|----------|---------|
| [`python/`](python) | Python 3.9+, zero dependencies | `erupt-sdk` (PyPI) |
| [`go/`](go) | Go 1.21+, standard library only | `github.com/erupt-io/erupt-sdk/go` |
| [`ts/`](ts) | TypeScript / Node.js 22+, zero runtime dependencies | `erupt-sdk` (npm) |
| [`php/`](php) | PHP 8.1+, zero Composer dependencies | `erupt-io/erupt-sdk` (Packagist) |
| [`dotnet/`](dotnet) | C# / .NET 8+, no runtime NuGet dependencies | `Erupt.Sdk` (NuGet) |
| [`java/`](java) | Java 17+ | use `xyz.erupt:erupt-cloud-node` directly |
| [`conformance/`](conformance) | | protocol checks every SDK passes against the same fixture |
| [`schema/`](schema) | | the contract generated by erupt: annotation JSON Schema and field templates |

Every SDK serves: CRUD with search / sort / paging, CHOICE, dates, references (table and tree pickers),
row operations (with forms, confirm text, per-user visibility) and the server's per-user power; raw
annotation attributes are typed from and validated against `schema/`.

## Keeping in step with erupt

`schema/` is the whole contract between the two repositories. After an annotation change erupt regenerates
it (`mvn -pl erupt-test -Pnode-schema test`); here the `sync-schema` workflow (weekly, or run by hand with
a branch / tag of erupts/erupt) pulls it, regenerates every language's code and opens a pull request.
Each language's workflow fails on a generated file that no longer matches `schema/` and runs the
conformance suite; `databases` runs every SDK's SQL repository against real PostgreSQL and MySQL. A pull request opened with the workflow token does not trigger other workflows: close
and reopen it (or push to its branch) to run them.
